# 数据模拟规范

## 1. 虚构主体设定（数据的"世界观"）

先构建一个完整可信的虚构主体，写入 `DB.meta`：企业名、行业、组织片区、平台名与版本、安全运行天数、演示日期。全平台所有数据域都从这个世界观派生，保证人名、部门、地点、设备口径一致。

## 2. 剧本化原则（数据不是随机数，是"有剧本的一天"）

- **一条主线事件贯穿**：设计 1~2 个跨模块的贯穿性事件（如"某探测器数据断流触发法定 24h 处置倒计时"），让它在告警、隐患、设备、系统自监测等多处同源出现，形成互证。
- **一个"问题人物/对象"多处出场**：如低信用分员工在开票阻断、门禁拦截、钥匙柜拦截三处出现，演示管控机制的闭环。
- **数据之间要能对上账**：KPI 汇总数 = 明细条目统计值；地图标记数 = 台账条数；趋势图末端 = 当前值。数字矛盾是高保真原型的致命伤。
- **当日时间线自洽**：告警时间集中在演示日上午、状态分布符合"少量未确认 + 少量处置中 + 多数已闭环"的真实比例。

## 3. 字段真实感规范

| 维度 | 规范 | 示例 |
|---|---|---|
| 人名 | 30~40 个不重复真实感中文姓名，同一人跨数据域出现时姓名/部门/电话/角色四元一致 | 陈志远 · 机加车间 · 139****2107 |
| 编号 | 结构化前缀 + 日期 + 序号，全站统一体系 | `AL-0910-021`（告警）、`MT-0910-05`（维保单）、`HD-2026-062`（隐患）、`RX-031`（风险） |
| 时间 | 告警 `HH:MM:SS`、台账 `YYYY-MM-DD`、记录 `MM-DD HH:mm`、"刚刚/N 分钟前"相对时间并用 | `09:41:07` / `2026-09-10` |
| 电话 | 必须脱敏 | `138****4519` |
| 专业术语 | 使用行业真实标准与术语（国标编号、法规名称、行业术语），宁少勿错 | LEC 评估、GB 18218、SIL2（均为公开国标/行业标准术语） |
| 数值 | 带单位、带阈值上下文、带小数位真实感 | `CO 浓度 46ppm（一级预警值 40ppm）` |
| 内容文案 | 告警/事件描述写成完整业务句子，包含位置 + 对象 + 数值 + 处置状态 | 见上例 |

## 4. 数据规模参考

每个数据域：核心条目 5~15 条（足够分页/筛选演示）+ 汇总统计对象 + 1 个"演示模板池"（用于实时推送）。重点对象（如核心风险/重点票据）扩展子结构（条目清单/检测数据/审批流节点/关联资源）。
