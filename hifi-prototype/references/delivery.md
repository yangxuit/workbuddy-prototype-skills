# 交付节奏与模式 B 延续约束

## 1. 分批交付节奏

模块超过 3 个时：先交付 `index.html` 门户 + `_shared` 五层骨架（含第一批数据域），再按模块分批交付；每批交付的每个 HTML 必须双击即可独立打开运行、控制台无报错；门户卡片按 `delivered` 字段实时标注交付进度。

一次生成内容过大时，主动分批交付，每批以可独立打开运行的页面为准。

## 2. 模式 B 附加约束（延续已有项目）

- 先通读现有 `_shared` 四个 JS/CSS 与既有页面，**严格遵守既有 `DB` 数据域、`NAV_DOCS` 结构、设计令牌与类名体系**，只做增量扩展。
- 新数据域追加进 `mock.js` 对应模块编号下；新 API 追加进 `api.js` 并保持注释契约（见 references/architecture.md 第 2 节）；禁止在页面里另起数据源。
- 新页面沿用 `initAdminDoc`/`initDoc` 与 `XXSTATE.built` 模式；与既有页面交互范式保持一致（同一动作在老页面怎么反馈，新页面就怎么反馈）。
- 跨模块联动（如告警回流、待办跳转）必须接入既有机制，不得另建平行通道。
