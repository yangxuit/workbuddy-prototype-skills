# 演示放映机（demo-tour）

## 概述

把"自由浏览式原型"升级为"放映机式引导演示"——演示者无需背稿、无需记路径，跟着底部悬浮引导条走：**开始 → 下一步 → …… → 结束演示**。适用于任何纯静态 HTML 原型（不限于 hifi-prototype 技能的产物）、hash 路由多页站点。

冲突仲裁优先级：**数据同源 > 演示连贯 > 视觉规范 > 站点数量**。

三条铁律：

1. 讲解词必须可直接照念：口语化、有卖点、信息密度适配受众；禁止"这里展示的是……"式空转描述。
2. 演示数据与页面数据同源：讲解词中引用的编号/数值/人名必须来自原型真实数据，禁止编造。
3. 任何一步不允许白屏/卡死：跨页跳转、视图切换失败必须有兜底（跳目标页/激活默认视图）。

## 工作流

### 第 1 步 · 判定演示对象来源

两种模式任选其一：

- **手填模式**：用户已明确演示对象与站点序列 → 直接进入第 3 步编排。
- **推导-确认模式**（跨原型复用时推荐，用户说"AI 推导"或未指明对象时默认采用）：先只通读原型（门户卡片、模块清单、mock 数据域、贯穿性事件、记录关联等信号），推导候选清单——格式 `候选ID｜动线名｜一句话核心看点｜覆盖页面/模块｜建议站数`，个别对象附降档建议与理由——**经用户确认后才进入编排，未确认不得动工**。

### 第 2 步 · 收集配置槽位

可选槽位（未提供时按默认执行，不追问）：叙事链模式（默认按对象适配：客户评审取深度贯穿链 8~12 站，单场景取四段链 4 站，展会快闪取速览链 2~3 站）、目标受众、演示时长（默认 8~10 分钟，时长守恒：每站讲解词约 50~75 秒）、讲解词风格（对外售前口语卖点型 / 评审汇报严谨型 / 培训教学引导型）、互动提示（默认开启）、聚焦高亮样式（默认橙色脉冲描边）、引导条位置（默认底部居中）、主题适配（默认 AI 自动探测）、进度持久化（默认 sessionStorage）、派生工厂（≥3 条同构动线时启用）。

配置全表与三种典型场景填写示例见 references/config-reference.md。

### 第 3 步 · 引擎接入与动线编排

- 引擎六项能力规范（跨页跳转、进度持久化、视图切换、元素聚焦、双主题适配、结束清理）与防御性实现要点 → **必读** references/engine-spec.md
- 站点编排规范（站点字段结构、首末站规则、叙事链三选一、派生工厂）→ **必读** references/orchestration.md
- 数据同源铁律（动线数据与业务 mock 同层存放、讲解词引用真实数据、入口可用性自动判定）→ references/engine-spec.md 第 4 节

assets/ 内含：

- `assets/tour-engine.js` — 已按引擎规范实现并实测的放映机引擎（含跨页恢复、时间上限轮询聚焦、筛选/选中协议）。目标原型无同类引擎时，直接复制接入并在其上做主题适配，禁止从零重写引入回归。
- `assets/example-baoxiu/` — 完整参考实现（报修闭环 4 模块 + 引擎接入 + 动线数据），展示引擎与原型数据的正确接法。

### 第 4 步 · 交付前验收

按 references/acceptance.md 清单走查：无头浏览器（或逐站人工）走完全部站点零 JS 错误；跨页跳转后进度正确恢复；每站 focus 聚焦命中（异步元素轮询等待后命中，勿切站后立即断言）；讲解词引用编号逐一对得上页面数据；结束清理干净无残留。

## 与 hifi-prototype 技能的衔接

目标原型若为本技能同仓库的 hifi-prototype 产物，其 `_shared` 层结构（DB 数据域、NAV_DOCS）是推导候选动线的首选信号源；引擎可直接并入其 `_shared/tour.js`。
